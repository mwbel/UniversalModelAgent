## Current Feature Context

The OCR page is intended to support a correction workflow:

1. Left column: original PDF page image.
2. Middle column: MinerU full-book Markdown rendered in a Typora-like view.
3. Third column: high-risk MinerU blocks for block-level Mathpix correction.
4. Fourth column: full-page Mathpix reference, generated by the existing top button `整页 Mathpix（备用）`.

Core user goal:

```text
Use free MinerU as full-book first draft, then call paid Mathpix only on high-risk blocks or full pages when needed.
Mathpix should be a correction reference, not a replacement for the whole MinerU pipeline.
```

## Known Failing Examples

### Example A: MinerU single-line display math rendered as raw source

MinerU may emit display math on one line:

```md
$$\widehat {f}(x) = \left\{ \begin{array}{ll}0, & 0 \leq x < 1, \\ 1, & x \geq 1. \end{array} \right.$$
```

Expected:

```text
Render as MathJax display math, not as raw `$$...$$` text.
```

Relevant functions:

```text
renderMarkdownHtml()
isDisplayMathStart()
collectDisplayMathBlock()
renderDisplayMathBlock()
```

### Example B: Mathpix broken aligned environment

Mathpix can emit invalid nested `$$` delimiters:

```md
$$\begin{aligned}
$$
\sqrt { x } & \leq ...
$$
$$
& = ...
$$
\end{aligned}$$
```

Expected normalized form:

```md
$$
\begin{aligned}
\sqrt { x } & \leq ...
& = ...
\end{aligned}
$$
```

Relevant functions:

```text
prepareMathpixMarkdown()
repairBrokenDisplayMathDelimiters()
removeDanglingSingleDollarLines()
normalizeSingleLineDisplayMath()
```

### Example C: Third column expansion behavior

User expectation:

```text
When a page loads, the current/first high-risk block should be expanded enough for inspection.
After Mathpix correction, only the corrected current block should expand.
Other blocks should remain collapsed.
```

Relevant functions/state:

```text
reviewExpanded
reviewInitializedPages
ensureDefaultReviewExpansion()
expandOnlyReviewBlock()
renderReviewItem()
```
